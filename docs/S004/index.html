Tokens: o200k_base over the JSON of each part, one ruler for every vendor. Total includes the message envelope and the prompt itself (about 30 tokens). Three runs per harness; tool schemas byte-identical across runs. The last row is ours: pi plus our own 47 KB CLAUDE.md.

How it was counted

Each harness ran with a scratch HOME and a fake key, pointed at a local capture endpoint (cap.ts) that writes down every request and answers "NONE". The main request is the largest one carrying the prompt. tokens.py splits it into tools, system and the rest. Raw bodies hold vendor system prompts and are not published.

The tool list is not fixed per version. With CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1, Claude Code 2.1.287 drops PushNotification, Monitor and DesignSync: 20 tools, about 4,000 fewer tokens.

These are clean installs with no MCP servers and a two-line instruction file. Real setups are bigger. That is the open question.

Add your row (about a minute)

  1. Claude Code: fresh session in an empty directory, run /context, add system prompt + tools + MCP tools + memory files.
  2. Your own API calls: send hi as the only message with your normal tools attached, read usage.input_tokens.
  3. Any harness with a base-URL setting: PORT=18100 OUT=./cap bun cap.ts, point the harness at it, then python3 tokens.py ./cap.

Changelog

A GitHub Actions job checks npm, PyPI and GitHub releases every day. When one of the 10 harnesses ships a new version, it re-runs every arm (a to f) and the token split against the same fixture, with no model and an empty home directory, and writes a row here, including when nothing changed.
