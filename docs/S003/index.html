Does your coding agent load the instruction files and hooks you think it loads? A file the harness skips looks exactly like one it reads. Nothing errors. The session just runs without it.

In September, a post showed that Claude Code reads AGENTS.md only when a remote feature flag resolves, so with telemetry off the file was skipped without a warning (485 points on Hacker News, since marked fixed there). The author caught it with a canary word. S003 runs that check on every instruction surface, on every harness someone will try it on.

What we found on our own stack

All 11 hooks are dead. Our config registers 11 hook commands, 5 of them PreToolUse guards. They were written for Claude Code. The harness we actually run reads no .claude/settings.json at all, so none of them runs, and nothing says so. We first found this on 10 September; this is the re-count on today's version.

Skills load as a list, not as text. 33 of our 34 skill files show up by name and description. The 34th sits in a folder starting with a dot, which the loader skips. No skill body is in context until the agent opens it.

Same repo, different instructions. pi takes one file per directory, in the order AGENTS.override.md, AGENTS.md, CLAUDE.md. Claude Code's loader reads AGENTS.md only "where the project has no CLAUDE.md" (as quoted from its code in the post above). A repo with both files gives a pi session one file and a Claude Code session the other.
