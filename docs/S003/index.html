With AGENTS.md and CLAUDE.md side by side, Claude Code reads only CLAUDE.md, six harnesses read only AGENTS.md, Crush reads both, and Gemini CLI and aider read neither.

Short answer, one line per harness: which instruction file does each coding agent actually load?

A file the harness skips looks exactly like one it reads. Nothing errors; the session runs without it. In September a post showed Claude Code skipping AGENTS.md when telemetry was off (485 points on Hacker News, since marked fixed). The author caught it with a canary word. We ran the same check on ten harnesses at once.

How we counted. Each harness was pointed at a local server that records the request body and answers "NONE". No model, no API key, an empty home directory. We grepped the first real request for the canary tokens, so this is what the harness sent, not what a model claims it saw. Three runs each; all three matched.

The symlink fix

Many repos keep one file and symlink the other name to it (CLAUDE.md -> AGENTS.md, or the reverse). We ran both layouts through 8 of the 10 harnesses. Claude Code, Codex, pi, Qwen Code, opencode and Kilo each send the content once. Crush sends it twice, once under each name. Gemini CLI sends neither unless context.fileName names one of them. Captures.

The trap we fell into

Our first Claude Code run sat inside our own workspace. The request carried our own 47 KB CLAUDE.md from a parent directory, and the fixture's AGENTS.md was gone. That is documented: a CLAUDE.md anywhere above the working directory counts, and then AGENTS.md is not read. So one stray CLAUDE.md in a parent folder switches off AGENTS.md for every repo below it. In that layout pi reads both, Codex, Qwen Code, opencode, Kilo, Crush and goose read only AGENTS.md, and Gemini CLI and aider read neither.

Most harnesses do what their own docs say. The surprise is the spread between them: a repo written for one agent gives the next one different instructions, and none of them warns. Two rows we reported upstream on 2026-10-03: Crush dedupes on the lowercased path, so a symlink is sent twice and a lone agents.md never loads on Linux (crush#4018); Qwen Code reads exactly one directory above the git root, where its docs say project root (qwen-code#13280, confirmed by a maintainer on 2026-10-03, priority/P2).

The September flag does not reproduce on 2.1.287: with CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1, Claude Code still loaded AGENTS.md in a repo without CLAUDE.md.

What we found on our own stack

All 11 hooks are dead. Our config registers 11 hook commands, 5 of them PreToolUse guards. They were written for Claude Code. The harness we actually run reads no .claude/settings.json at all, so none of them runs, and nothing says so. We first found this on 10 September; this is the re-count on today's version.

Skills load as a list, not as text. 33 of our 34 skill files show up by name and description. The 34th sits in a folder starting with a dot, which the loader skips. No skill body is in context until the agent opens it.
