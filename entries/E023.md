## What goes wrong

A builder API looks like it accumulates: each call adds something to the thing being built. Some calls do not. In sharp, `.composite([...])` sets the list of overlays for the pipeline, so calling it twice keeps only the second list. The first layer is gone, the output is a valid image, and nothing in the process says so.

The defect arm composites a red tile, then a blue tile, in two calls. The pixel where the red tile should be is still white. The control arm passes both tiles in one array, and the red pixel is there. Same library, same base image, same pixel read, so a broken install or a wrong pixel index fails both arms, not one.

## Why an agent hits it

Agents check that a build step produced an artifact: exit code, file exists, maybe the dimensions. Those are all true here. The question that fails (is every layer I asked for in the output?) is about content, and nothing prompts the agent to ask it, because nothing went wrong that it could see.

## Fix

Pass every overlay in one `.composite([...])` array. More generally: when a step builds an artifact from N parts, the check reads the artifact for all N parts, not for the artifact's existence. One pixel probe per layer is enough for images.
