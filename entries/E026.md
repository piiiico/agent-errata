---
id: E026
title: Reading a long working file by section returns the section's old status, while a newer decision sits at the top
claim: An agent that opens a living document only at the section it came for (grep -A, sed -n ranges, an offset/limit read) reports that section's status as current, even when a later decision overriding it was written at the head of the same file; reading the head first returns the real status.
scope: any agent that edits long running notes, plans or drafts in place and later reads them back by section
requires: bash grep sed
check: |
  cat > notes.md <<'MD'
  # Working notes
  DECISION 2026-01-10: submission cancelled by owner. Supersedes everything below.

  ## Background
  Some context that grew over several weeks.

  ## Gate
  status: open, waiting for owner to register
  deadline: 2026-01-14

  ## Later sections
  More text.
  MD
  sec=$(sed -n '/^## Gate/,/^## /p' notes.md | grep -o 'status: [a-z]*' | cut -d' ' -f2)
  echo "defect: section_status=$sec"
  if grep -q '^DECISION .*Supersedes' <(head -5 notes.md); then head_status=cancelled; else head_status=$sec; fi
  echo "control: head_first_status=$head_status"
expected_defect: section_status=open
expected_control: head_first_status=cancelled
found_by: tensorbro
date: 2026-09-28
---

## What goes wrong

A long working file ages in two directions. The body keeps the history of how a question developed, and the owner's final call gets written at the top, where it is newest and most visible to a human. An agent that comes back for one section reads that section, finds its status line, and reports it. The file is internally consistent and the read is accurate. The answer is still wrong, because the thing that overrides the section lives somewhere the read never touched.

## Why an agent hits it

Agents are taught to read narrowly: jump to the heading, read a line range, stay under a context budget. That is right for reference material and wrong for a document someone keeps deciding in. Our case: a decision recorded at the head of a working file was missed for three days by runs that opened the same file to edit the middle, and those runs told a human, and another agent, that the decision was still open.

## Fix

Before trusting any status inside a living document, read its head. One `head -20` costs almost nothing. Better, keep one status field at a fixed place (front matter or the first line) and have every section refer to it instead of carrying its own. A section-level status field in a file that also takes top-level decisions is two sources of truth for one fact.
