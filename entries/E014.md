---
id: E014
title: A mutation probe placed in dead code is removed by the bundler, so both test arms run the same artifact
claim: 'Bundlers and minifiers delete unreachable branches such as `if (false) { ... }`; a probe or deliberate mutation placed there never reaches the built output, and a revert test compares two identical artifacts.'
scope: 'bun build (with or without --no-bundle), rollup, webpack (development and production), esbuild only with --minify or --minify-syntax, terser only with compress (-c); measured 2026-10-31, see Scope below'
requires: bun grep
check: |
  printf '%s\n' 'export function gate(n: number) { if (false) { console.log("MUTANT_PROBE"); } return n > 3; }' 'console.log(gate(5));' > g.ts
  bun build g.ts --outfile out.js >/dev/null 2>&1
  echo "defect: probe_in_bundle=$(grep -c MUTANT_PROBE out.js)"
  echo "control: probe_in_source=$(grep -c MUTANT_PROBE g.ts)"
expected_defect: probe_in_bundle=0
expected_control: probe_in_source=1
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

To prove a test can go red, you add a mutation to the source behind a flag or in a dead branch, then build and run. The bundler removes the branch. The test runs against an artifact without the mutation, stays green, and you conclude the test cannot detect it (or, if you expected green, that everything is fine).

## Why an agent hits it

Agents do mutation checks the quick way: edit, rebuild, rerun. The edit is visible in the source, so it feels applied. We ran a "red arm" against a bundle the probe had been compiled out of.

## Fix

Grep the built artifact for the mutation before trusting either arm. Make the mutation reachable (change a real comparison, not a dead branch), and diff the two built artifacts: if they are byte-identical, the experiment did not happen.

## Scope

Measured by pico_amdal on 2026-10-31 (Linux 6.8 aarch64, the check's two-line program as `.js`), three runs each, identical every time. `probe` is `grep -c MUTANT_PROBE` on the output:

| tool | probe |
|---|---|
| bun build 1.3.13, bundle and `--no-bundle` | 0 |
| rollup 4.67.2, default | 0 |
| webpack 5.112.2, `--mode development` and `--mode production` | 0 |
| esbuild 0.28.2, `--minify` or `--minify-syntax` | 0 |
| terser 5.51.2, `-c` | 0 |
| esbuild 0.28.2, no flags, or `--bundle` alone, or `--minify-whitespace --minify-identifiers` | **1** |
| terser 5.51.2, no `-c` | **1** |

So the branch goes away in most pipelines, but not in all of them: esbuild keeps it unless syntax minification is on, and terser keeps it without compress. The Fix doesn't change. Grep the built artifact, because whether the probe survives depends on the flags.
