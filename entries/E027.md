id: E027
title: A regex pattern built from an ordinary string turns \b into a backspace, so the guard matches nothing and looks like it has nothing to block
claim: 'In JavaScript and Python, "\b" inside an ordinary string literal is the backspace character (0x08), not the regex word boundary. A guard pattern assembled from strings, such as new RegExp("\bfind\b"), looks for backspace+find+backspace, which no command contains. It never denies anything, it throws no error, and printing the pattern shows \bfind\b, so a quick look says it is fine.'
scope: any guard, filter or linter rule whose regex is built from strings (new RegExp, re.compile on a non-raw string, patterns concatenated from parts or loaded from JSON). The check uses node
requires: node
check: |
  node -e '
    const cmds = ["find ~ -name x", "find / -type f", "ls; find . -name y", "cd a && find ~ -newer z", "x | find /home -iname q"];
    const built   = new RegExp("\bfind\b");
    const escaped = new RegExp("\\bfind\\b");
    const count = (re) => cmds.filter((c) => re.test(c)).length;
    console.log("defect: string-built guard denies " + count(built) + " of 5 searches");
    console.log("control: escaped guard denies " + count(escaped) + " of 5 searches");
  '
expected_defect: string-built guard denies 0 of 5 searches
expected_control: escaped guard denies 5 of 5 searches

## What goes wrong

A guard blocks slow recursive searches by matching `\bfind\b`. Someone tightens it by building the pattern from pieces, so that the tool name has to sit at a command position. Inside an ordinary string literal, `\b` is an escape for backspace, which uses up the backslash before the regex engine ever sees it. The pattern now requires a backspace character on each side of `find`. No command contains one, so the guard denies nothing.

The defect arm runs five searches the guard exists to stop through the string-built pattern, and it denies 0. The control arm writes the same pattern with the backslashes doubled, and it denies 5. The only difference between the two is one level of escaping.

## Why an agent hits it

A guard that has stopped matching prints the same thing as a guard with nothing to complain about, which is nothing. Allow-only tests stay green, since everything is allowed. Logging the pattern doesn't help either: `JSON.stringify` prints the backspace as `\b`, and many consoles show nothing at all for it. You only find out when you test the denials, not just the allows.

## Fix

- Write patterns as regex literals (`/\bfind\b/`) or raw strings (`r"\bfind\b"` in Python, `String.raw` in JS). When you do assemble from strings, double every backslash.
- Test both directions: cases that must be denied as well as cases that must pass. A guard is only tested once a known-bad input has failed through it.
- To inspect a built pattern, print its code points, not the string: `[...re.source].map(c => c.charCodeAt(0))` shows 8 where the word boundary should be.
