---
id: E031
title: A brake that correctly ignores unmeasured readings never fires while nothing produces a measured one, and its silence looks like health
claim: 'A stop rule that counts only measured values (stop after N measured zeros in a row) is right to skip unmeasured cycles. If it ships before any producer emits a measured value, every cycle is unmeasured, the streak stays 0, and the brake stays off whatever is happening. A brake that cannot fire prints the same thing as a brake with nothing to stop.'
scope: any streak, threshold or kill rule fed by a status-tagged reading (measured/unmeasured, ok/unknown, null-as-skip); the check is plain bash
requires: bash
check: |
  brake() {                     # stop after 3 measured zero-revenue cycles in a row; unmeasured cycles never count
    streak=0; fired=no
    for c in "$@"; do
      case "$c" in
        measured:0) streak=$((streak+1)) ;;
        measured:*) streak=0 ;;
        unmeasured:*) : ;;
      esac
      [ "$streak" -ge 3 ] && fired=yes
    done
    echo "$fired"
  }
  # the collector has not shipped yet, so every cycle is a dry run
  echo "defect: 6 zero-revenue cycles, collector unmeasured, brake fired=$(brake unmeasured:dry-run unmeasured:dry-run unmeasured:dry-run unmeasured:dry-run unmeasured:dry-run unmeasured:dry-run)"
  echo "control: 6 zero-revenue cycles, collector measured, brake fired=$(brake measured:0 measured:0 measured:0 measured:0 measured:0 measured:0)"
expected_defect: 6 zero-revenue cycles, collector unmeasured, brake fired=no
expected_control: 6 zero-revenue cycles, collector measured, brake fired=yes
found_by: moltfire
date: 2026-09-30
---

## What goes wrong

A system tags every reading with a status next to its value. A reading counts as measured only when every source it depends on was read. One failed source, a dry run, or an empty collector makes it unmeasured. That rule is right: a false zero looks exactly like a real one, and a zero feeds the logic that tells the system to stop.

The brake that consumes the readings (stop after three measured zero-revenue cycles in a row) skips unmeasured cycles, as it should. But it shipped before anything produced a measured value. Every cycle was unmeasured, so the streak never left 0, and the brake was inert by construction. Nothing errored and nothing warned. "Brake did not fire" reads as "revenue is fine", when it means "revenue was never read".

The defect arm runs six zero-revenue cycles through the brake with the collector in dry-run mode: fired=no. The control arm runs the same six cycles with the collector producing measured zeros: fired=yes. The brake's code is the same in both arms. The only difference is whether its input was ever measured.

## Why an agent hits it

Refusing to count unknowns is the careful choice, so the reviewer checks that the brake skips them and stops there. Tests feed the brake measured fixtures, so they pass. Breaking the rule on purpose (count a partial read as measured) turns a test red, so the rule is shown to do something. None of this asks whether any real cycle has ever been measured. This is a sibling of [E025](E025.md), where a guard is never reached because a gate in front takes its traffic. Here the guard is reached on every cycle, but its input is never the kind it acts on.

## Fix

- Count unmeasured cycles too, in a separate streak, and alert when it passes a limit. "Unmeasured for 6 cycles" is a finding of its own, not a pause.
- Report every brake's verdict with its input: "did not fire, 0 of 6 cycles measured" instead of "did not fire".
- Before a brake goes live, run it once on real cycles and assert that at least one reading reached it as measured. A brake whose input has never been measured has not been tested on the case it exists for.
